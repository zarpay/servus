- [ ] Validate event payloads against handler schemas when emitted via the `emits` DSL (currently only validated when using `Handler.emit`). See `Emitter#emit_events_for` — should call `Validator.validate_event_payload!` for each handler that defines a `payload_schema`.
- [ ] Add automatic logging for event emissions. Currently `Bus.emit` uses `ActiveSupport::Notifications.instrument` but nothing subscribes to log them. Events are instrumentable but not logged by default — the YARD comments in `Bus` incorrectly claim they appear in Rails logs.
- [ ] Log guard failures. Currently when a guard throws `:guard_failure`, it unwinds past the `benchmark` block so `Logger.log_result` never runs. Guard failures are silently converted to failure Responses with no log entry. Consider logging the guard failure (with the GuardError message and duration) after the catch block in `Base.call`.
- [ ] Add a `config.require_schemas` option (default: false) that raises an error when a service is called without an arguments schema defined. Useful for teams that want to enforce schemas across all services. Could also support `config.require_result_schemas` separately. Additionally, consider a test helper or RSpec matcher like `expect(Treasury::TransferGold::Service).to have_schema(:arguments)` for CI enforcement.
- [ ] Add RSpec matchers for response assertions: `be_guard_failure(code)`, `be_service_failure(ErrorClass)`, and `be_service_success`. Would reduce multi-line assertions like `expect(result).to be_failure; expect(result.error).to be_a(GuardError); expect(result.error.code).to eq("x")` down to `expect(result).to be_guard_failure("x")`.
- [ ] Add test helpers for building Response objects: `servus_success_response(data)` and `servus_failure_response(message, type:)`. Currently tests must use `Servus::Support::Response.new(true, { ... }, nil)` directly, which is verbose and exposes the internal constructor.
- [ ] Clean up Guard so that `test` reads from instance variables instead of accepting kwargs. Currently `execute!` passes the same kwargs to both `new` and `test`, which is redundant — `initialize` already stores them as `@kwargs` with `method_missing` access. `test` should be a zero-argument method that reads from the instance. This also simplifies testing since you only pass args to `new`.
